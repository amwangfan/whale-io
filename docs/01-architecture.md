# 01 · 总体架构：模块如何注入官方固件而零侵入

## 设备与栈

- **眼镜**：雷鸟 iO，主控 BES2700（Cortex-M33，Thumb-2，FPv5 浮点），NuttX RTOS，定制 LVGL。
- **手机**：Android，运行厂商宿主 App（与眼镜 BLE 通信）。
- **我们的两层改动**：眼镜固件里注入一个自研模块（TVP2C）；手机宿主里注入一个 addon（Java/dex 层钩子）。

## 固件侧：补丁点注入

核心思想：**不改原厂逻辑，只在关键函数入口搭桥**。

```
原厂函数入口
  ↓ 补丁（BR 分支钩 / IMM 立即数，覆盖函数序言字节）
我们的蹦床（trampoline）
  ├─ 复刻被覆盖的原厂序言字节
  ├─ 执行我们的逻辑（或仅记录/转发）
  └─ b.w 跳回 resume 地址（= 钩点 + 覆盖长度 + 1）
```

- 全项目共 **40 个补丁点**：菜单挂载、事件分发、文件接收、显示页生命周期等。
- 模块本体（~220KB）编译后嵌入固件包的空闲区，链接时用链接脚本把所有符号钉到目标版本的实测地址。
- **地址重定位**：换基线版本时，所有符号用「前缀字节唯一性 + 结构匹配 + 调用图 + 常量簇」多重定位，逐符号找回——不靠猜。

### 关键纪律：补丁必须打在「活代码」上

官方固件里存在与活代码**逐字节相同的死副本**（历史遗留/对齐填充）。补丁打错了副本：离线审计看不出（字节一致），真机上钩永远不触发。**每个补丁点必须在最终产物里反汇编对账**，确认落在真实执行路径上——并且仿真要走「真实蹦床路径」，不能按符号直接跳进模块函数自证。

## 手机侧：addon 钩子

宿主 App 是厂商 APK。我们的 addon 通过 dex 层钩子挂在它的消息/文件传输路径上：

- **队列钩**：挂在消息队列的静态分发必经之路上，截获/观察眼镜回执；
- **文件钩**：挂在文件发送实现上，接管自定义文件的传输；
- 版本适配用「ABI 映射表」：厂商每次发版混淆类名会变，我们维护一张版本→类名的映射（运行时反射用一份、dex 钩子用一份），新版出来时只需重导这张表。

## 云端（可选）

眼镜本身不联网；云端智能体经手机中转：

```
眼镜（语音文本）→ 手机 addon → HTTPS → 云端智能体（whale-core，自带记忆/人格/门控）
                                    ← 回复/卡片 ←
```

- 聊天与执行分离：`/v1/chat` 纯对话；`/v1/agent` 带工具循环，自由 shell/写文件/自修改一律**两阶段确认**（镜片原文回显将要执行的内容，确认后才执行），高危模式硬拒绝。
- 云端部署自行其是；公开仓 [whale-core](https://github.com/amwangfan/whale-core) 是智能层契约（事件 in / 意图 out），不含设备细节。

## 数据流一图

```
[原厂系统] ←── 补丁点（零侵入）──→ [TVP2C 模块] ←── TDP 会话 ──→ [手机 addon] ←── HTTPS ──→ [云端智能体]
  菜单/事件/显示                     菜单应用/显示运行时              门控/桥接/重试              记忆/人格/任务
```
