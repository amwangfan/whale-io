# 02 · 模块开发指南：菜单、帧动画、LVGL、编译链接

## 菜单挂载

原厂菜单是一个固定 8 项的轮播。我们把它扩成 13 项（8 原厂 + 5 模块）：

1. **count 补丁**：把菜单项数立即数从 8 改为 13（`movs r1, #0xd`）；
2. **扩展结构**：在原厂菜单结构体尾巴上挂我们的字段（菜单结构体 6.11 偏移：rows@0xc、labels@0x2c、icons@0x4c、dots@0x70、当前 index@0x98、帧缓存@0x9c……完整偏移表需按你的基线重导）；
3. **事件钩**：原厂事件处理器（旋钮/点击）入口处分发——index 8..12 走我们的模块，其余交还原厂；
4. **帧动画**：菜单项图标是逐帧动画，`frame_start(i)=15+30·i`，帧域 0..389，lottie 帧数上限 225——模块项的帧区间排在原厂项之后。

## 模块应用的结构

每个模块应用是一个独立 C 文件组，标准骨架：

```
mymodule/
  mymodule.c           // LVGL 页面、输入处理、生命周期
  mymodule_service.c   // 业务逻辑（与 UI 解耦）
  mymodule_native.c    // 与原厂符号的桥接（钉在链接脚本里的地址）
```

生命周期纪律：

- **create pin 必须用对**：LVGL 对象创建函数地址要逐个在目标固件里实证（我们曾把 canvas create 错指到按钮 create——对象尺寸不足导致越界写堆崩溃）；
- **类描述符 = PSRAM 数据段镜像**，静态可读 instance_size，建对象前先核对尺寸；
- 模块项打开时打印一行 trace（如 `[MyModule] event=N result=M`）——这是真机排障的唯一可靠眼睛。

## 编译与链接

- **工具链**：LLVM（clang + ld.lld）交叉编译 ARM/Thumb-2；主机端单元测试用 gcc（注意 clang 无主机头文件）；
- **链接脚本**：每个用到的原厂符号钉一个地址（`symbol = 0x10xxxxxx;`），换基线版本时全表重导；
- **审计**：构建产物与原厂对应区的差异必须逐字节解释——我们的标准是「40 个补丁点 + 模块区」之外零差异。

## 菜单精简（可选）

想减项而不是加项：菜单级删除 = 不建槽、不路由、代码保留（dormant）。要物理删除时先做**可达性审计**（调用图标 unreachable + 仿真加固），注意别把活基础设施删了（我们的教训：一个「死文件」里可能藏着别处在用的活函数）。

## 测试

- 每个模块配 gcc 主机端单测（逻辑层）；
- Unicorn 仿真跑**真实 Thumb-2 编译产物**（不是符号直入）：CHUNK 通路、守卫边界、开关页生命周期；
- 仿真假象要识别（如 Unicorn 不支持 ARMv8.1-M 的 LOB 与部分 FPv5 指令——这类 fault 是工具假象，不是固件 bug），假象与真问题分开记录。
