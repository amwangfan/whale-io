# 03 · TDP 显示协议规范

TDP（Turbo Display Protocol）是手机与眼镜之间的自定义显示会话协议：手机把灰度帧推到眼镜，眼镜自动开页显示。用于问候卡片、通知卡片、自定义提示等一切「镜片画布」场景。

## 传输载体

- 走厂商 BLE 通道之上的自定义文件传输：文件 `turbo-display.tdp`，TDP1 信封；
- 回执走厂商的 business-15 通道，40 字节定长（TDR1）。

## 操作码

| op | 名称 | 含义 |
|---|---|---|
| 1 | QUERY | 问眼镜：能不能收？（顺便拿到能力通告） |
| 2 | RECT | 宣告绘制区域 |
| 3 | KEEPALIVE | 保活 |
| 4 | CLOSE | 关页 |
| 5 | BEGIN | 开一帧事务（携带 tx） |
| 6 | CHUNK | 一个数据分片 |
| 7 | COMMIT | 提交上屏 |
| 8 | ABORT | 中止事务 |

## 一帧的生命周期

```
QUERY → (能力通告) → BEGIN(tx) → CHUNK × N → COMMIT → 眼镜渲染上屏 → CLOSE
```

- 512×128 灰度 = 65,536 像素；默认档每包 512B（净荷 472B），一帧 139 包；
- 每个关键动作都有回执；回执双通道（事件回执 + 数据回执）都要等，缺一会误判。

## 会话三要素（重要）

| 字段 | 含义 | 规则 |
|---|---|---|
| sid | 会话号 | 每次握手分配；眼镜重启归零 |
| revision | 代际号 | 占页内容换代递增 |
| tx | 事务号 | 每帧递增；**手机侧要持久化 highwater**，App 重启后不许回退 |

## 失步与恢复（STALE）

眼镜用回执结果码报告失步，**回执自带恢复所需的 sid/revision**——不要盲重试：

| 回执 | 语义 | 恢复 |
|---|---|---|
| NO_SESSION | 页槽不存在（固件没起过会话） | 走完整握手重开 |
| STALE（sid=0） | 眼镜冷启动 | 重定基 |
| STALE（sid=我） | 我的会话但 rev 旧了（比如眼镜重启过） | 按回执 rev 重定基 |
| STALE（sid=别人） | 页被别的功能占着 | 按产品策略：关页重开 / 或暂缓推送（见下） |

纪律：

- **连接/重连后首包必须 QUERY**——「可选」就是病根（我们踩过：重启后会话号全变，直接 BEGIN 必被拒）；
- 恢复序列每步间隔 ≥100ms 等双回执；CLOSE 后 ≥200ms 再 BEGIN（否则 CLOSE 会吃 BUSY）；
- **眼镜忙（BUSY）**：渲染一帧 <100ms，手机侧 300ms 短延迟重试即可；STALE/NO_SESSION 保持致命，不重试。

## 占页策略（产品层）

显示页同一时刻只能有一个占有者。占页时收到新推送，两种策略可选：关掉当前页强推（打扰）；或保留当前页、改往手机通知栏发一条提示、内容延后重推（礼貌）。建议做成**按内容类型可配的策略表**，不同卡片不同待遇。
