# 05 · 受门禁的安全刷写流程

刷固件是本项目唯一可能变砖的环节。我们的原则：**AI 永远不自主刷机，人当面执行，全程受门禁约束**。

## 流程概览

1. **制品核对**：候选包、回滚包逐字节核哈希，回滚包必须就在手边；
2. **手机侧准备**：候选包推送到手机指定目录（清掉旧候选），配套宿主 App 装好；
3. **真机人工核对**：眼镜电量 ≥50%、回首页、结束全部任务、ADB 观察通道可用；
4. **导入与校验**：在 App 内导入候选包，门禁逐项校验（包结构、内容哈希、版本一致、电量、空间、空闲）；
5. **一次性授权**：人工输入本次的授权标记才解锁安装——授权一次有效、用完即焚；
6. **安装**：不断连、不关机、不起其他任务；
7. **结果保护**：刷后必须人工确认看到自定义内容（我们的 MARKER），才解除保护闭环。

## 回滚

- 未变砖：同一受门禁流程刷回滚包；
- 变砖：停止，走官方售后/更深工程模式——**不要反复硬刷**。

## 门禁的实现要点（给自己做类似系统的人）

- 门禁状态机：LOCKED → ARMED → 传输中 → 结果保护 → release；每步都有 require 链，缺一即拒绝并计数；
- 刷写每一片都做字节比对（ pins 钉住候选包的尺寸与哈希），不对即拦；
- 授权落盘持久化（进程重启不丢），解除保护只认「真到了目标态/安全回退到底版」两种结果；
- 状态导出到一个状态文件（不含设备身份/固件正文），排障时第一手材料。

## 时间戳与日志坑

- 眼镜 syslog 时间戳是 **UTC**（比北京时间慢 8 小时）；
- syslog 是 RAM 缓冲，崩溃/重启丢当前会话——抓日志要趁热；
- 日志导出是多帧压缩格式，**只解第一帧会拿到一个整齐的截断窗口**（我们因此误判过一次「无痕迹」）——解包后先核对字节数再下结论。
