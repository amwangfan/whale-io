# 06 · 用 AI 复现的实操路线

本项目的大部分逆向、移植、测试都是在 AI 辅助下完成的。这条路线的要点不是「让 AI 写代码」，而是**让 AI 在每一步都有可验证的锚点**。照下面走，你可以在自己的设备上复现。

## 阶段 0：工具链

| 工具 | 用途 |
|---|---|
| apktool / jadx / dexdump | APK 解包与 smali 阅读 |
| capstone + Unicorn（Python） | 反汇编 + 仿真执行（跑真实编译产物） |
| LLVM（clang + ld.lld） | 模块交叉编译（ARM/Thumb-2） |
| MinGW gcc | 主机端 C 单元测试（clang 无主机头文件） |
| adb | 装机、取日志、推送制品 |
| 一台可刷的测试设备 | **别拿日用主力机/唯一设备练手** |

## 阶段 1：读懂原厂（纯研究，不改任何东西）

1. 解包官方固件与 App，画出你要挂接的子系统地图（菜单/事件/文件传输/显示）；
2. 给你要 hook 的每个函数建立「指纹」：前缀字节、结构特征、调用图邻居、引用到的常量；
3. 产出一张符号地址表 + 一份结构体偏移表——这是后面一切的地基。

**AI 用法**：把反汇编片段喂给 AI 做语义解读和候选定位，但**每个地址都要多路交叉验证**（前缀唯一 + 结构匹配 + 调用图 + 常量簇），AI 给的地址不直接用。

## 阶段 2：仿真先行（把崩溃消灭在真机之前）

1. 用 Unicorn 搭最小执行环境，加载原厂二进制片段 + 你的模块；
2. 跑通「钩子 → 蹦床 → resume」全路径：栈平衡、寄存器恢复、返回干净；
3. 已知工具假象要建表（如 Unicorn 不支持 LOB/部分 FPv5 指令）——假象与真问题分开记，不混淆。

**纪律**：能在仿真里排除的严重崩溃，绝不带上真机。

## 阶段 3：最小闭环

1. 只做**一个**最小改动（比如菜单只加一项空白页），跑通「改包 → 装 → 真机可见」全链路；
2. 加上字节级审计：产物与原厂的差异必须逐字节可解释；
3. 真机验证后再扩功能——每加一项都回到阶段 2。

## 阶段 4：健壮化

按 03/04 两节的会话与可靠性规则实现：首包握手、失步三分支恢复、有界重试、断路器、大分片档位。

## 坑位表（我们踩过的）

| 坑 | 现象 | 解法 |
|---|---|---|
| 死副本 | 补丁点字节对但真机不触发 | 补丁落点必须反汇编对账 + 仿真走真实蹦床路径 |
| create pin 张冠李戴 | 打开模块即崩（越界写堆） | LVGL 创建函数逐个实证，核对 instance_size |
| CRLF 行尾 | Windows 下打包管线静默误判 | 解码树全量转 LF + 管线读取入口统一归一化 |
| 日志截断窗 | 「零痕迹」误判 | 多帧压缩日志要读全部帧，先核字节数 |
| 会话号跨重启 | 重连后推送被拒（STALE） | 首包强制握手 + 按回执重定基 |
| 共享单闸门 | 优化传输拖垮其他功能 | 大分片优先，滑动窗口缓行 |

## 协作模式建议

如果你也用 AI 团队分工：研究岗（逆向/审计/出对照表）与开发岗（实现/验证）分开，协调者只派单、验收、同步状态——所有交接落文档（交接单 + 台账），任何人/会话接手都先读台账。
