# 鲸鱼陪伴能力意图规范（产品权威入口）

> **写给未来维护者的约定**：本文件描述“我们为什么要做、用户能得到什么、不同模块怎样联合生效”，不将外部参考项目的效果直接写成 whale-io 已完成功能。代码契约见 `whale-core/src/whale_core/`，真实部署状态见 [companion-roadmap.md](companion-roadmap.md)。
>
> 产品核心：**海内存知己，天涯若比邻。** “知己”来自持续理解与可靠记忆；“比邻”来自跨终端的可达性、主动但克制的陪伴。鲸鱼不能伪装拥有人的私人经历或感情；“心情”是可见、可关闭的角色表现状态。

## 一、总体验与边界

鲸鱼是**一个共享身份、多种交互前端**的 AI 伙伴，而不是两个独立机器人。其两个计算角色：

- **Realtime Omni / 多模态助手**：听、看、说、实时工具反馈；通话音频直接与实时多模态模型交互，不同步等待 DeepSeek。来源是手机/眼镜现场；低延迟优先。
- **DeepSeek / 陪伴好友**：长篇文字对话、深入探讨、对近期事件的非实时提炼、兴趣发现与主动表达候选。输出不能直接绕过权限策略执行。
- **共同鲸鱼层 Whale Core**：身份映射、记忆、上下文、角色状态、主动性策略、渠道选择、行动回执、用户反馈。模型只是其中的可替换思考器，不享有直接使用设备或第三方账号的权限。

| W01 | **实时助手** | 用户一开口就能得到自然回应，别因为 DS 串行 ASR→文本→TTS 卡顿 | Android PCM→Omni Realtime；转写回调异步写入记忆 | 音频直接回电话；转写只是未来记忆候选 | `infra/call-bridge/` 已有链路；真机需联调 |

| W05 | **未尽之事** | 昨天没讲完的事，在适合的时候能自然地接上，而不是定时“在吗” | 明确记录的未完成话题 + 来源事件 | `ProactiveDraft`（待审候选），交给 W06，不直接发 | `life/runtime.py` 有候选生成 |
| W06 | **主动性与克制** | 鲸鱼知道什么时候开口、什么时候不打扰；用户拒绝应当生效 | 事件候选 + 静默时段 + 忙碌状态 + 渠道授权 + 当日配额 + 审批 + 过期时间 | 拒绝/延后/待审批/可发；执行后记录尝试和渠道接收状态 | `life/initiative.py` 可测试；跨进程抢占待做 |
| W07 | **自主探索** | 鲸鱼可以在用户未发消息时发现真正有兴趣的内容，但不可假装看过 | **外部已授权、可核查的内容源**→兴趣匹配→带 URL 的发现候选 | 起草“发现了……要看看吗”→W06；深度阅读/日记需后续独立适配 | `life/discovery.py` 纯规划器；不实际爬取 |
| W08 | **反馈学习** | 用户能说“有用”“以后别提”“现在不想聊”，减少无效打扰 | 发送记录 + `useful/irrelevant/dismissed/not_now` | 写入反馈账本；后续策略需要使用反馈调整配额/主题 | `ProactiveOutbox.feedback` 存储已做，自动调参待做 |
| W09 | **多渠道** | QQ、手机、通话、眼镜是同一鲸鱼，而不是人格分裂 | 经过平台鉴权的消息 + 显式账号配对 | 标准化 `OwnerEvent` → Whale Core；回消息由各自适配器 | `life/channels.py` 身份入口已做；QQ 真连接未做 |
| W10 | **眼镜 HUD** | 重要但不紧急的信息轻轻出现，保持视觉简洁 | `show_card` 意图→经授权的 Dashboard Gateway→Turbo-IO | 眼前卡片，可选择暂不显示；不直接把长篇 DS 回答塞 HUD | 已有意图与实验链路；端到端需联调 |
| W11 | **主动电话** | 真正需要长时间说时才打电话，永远不能随意骚扰 | 候选理由 + 用户单独授权 + 单次确认 + 忙碌/静默校验 | `place_call` 经 VoIP 桥，拒接/无人接不能连环拨 | 现有 VoIP + Policy；生活层始终要求单次审批 |
| W12 | **手机/导航/环境感知** | 课表、天气、位置、导航等形成可解释的及时帮助 | 设备与天气/日程独立适配→`PerceptionEvent` | `ContextReasoner`→候选→W06→卡片/通话 | 事件契约/桩存在；真实源、权限 UI 尚未完成 |

**强制理解：** 每一个“想说话 / 发现内容 / 记住某事”都只是**候选**。只有 W06（授权与打扰）+ W09/W10/W11（实际渠道执行）完成，才算产生对用户可见的效果。模型生成的文本、来源文章、朋友发来的消息均不得自行授予 `urgent`、`approved` 或控制手机的权限。

## 三、优先级与触发规则

- **第一顺位：用户正在主动请求的实时交互**。通话直接走 Omni；只在音频回合完成后异步记录转写。同步记忆检索必须有严格超时预算，失败可跳过；DeepSeek 不在 PCM 必经路径。
- **第二顺位：用户设置的明确提醒**。日程/课程/天气经过真实数据源生成提醒候选，检查静默、重复与过期后才交给 HUD。
- **第三顺位：未尽话题或自主探索分享**。默认进入待审批草稿；即使配置自动发送，也只允许用户明示允许的低风险渠道，电话永远要单次批准。
- **最后：纯粹的闲聊主动开口**。不能基于“模型心情差”或“想念用户”的拟人设定施压；用户没回应时应减少而非提高频率。

## 四、用户必须有的控制

**默认配置关闭主动功能，但这不是产品禁区。** 用户完成对应账号/设备授权后，可以按需开启主动联系、主动电话、主动消息、QQ/B站代操作；运行时仍必须经过策略层与行动台账。每个渠道独立授权，不能由“我同意聊天”推导出“同意自主发消息”。

权限至少区分：记忆写入、环境采集、外部发现、每个消息渠道、主动通话；还需总暂停、静默时段、当日上限、记忆查看/删除、发送回执查看/撤回未来任务。录音、截图与环境听写仍须显式授权；系统 shell 的高危能力由独立硬性策略隔离，不受角色卡或主动性配置影响。

## 五、成功的判断标准

不是“后台有了定时器”“模型写了一段可爱的内容”，而是：

1. 我说过的事，经许可存成可信记忆，几天后在**适当情境**被准确想起；错误可以更正和删除。
2. 鲸鱼从实际证据发现新东西，能指出来源；没读过就不说“我看完了”。
3. 想主动分享时，先考虑当前情境、用户授权与自身配额；不打扰也是一次正确决策。
4. 同一记忆跨通话/文字/眼镜生效，且延迟不会迫使实时助手等待 DeepSeek。
5. 发送成功、投递失败、用户已读/未读互不混淆，能解释一次主动信息为何出现。
