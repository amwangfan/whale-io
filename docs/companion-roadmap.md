## P0 → P1 → P2 实施顺序

1. **先完成“真实闭环”**：电话转写→候选提炼→人工批准→持久化→DeepSeek 精准召回→眼镜草稿。先用本地单机联调证实，不直接打开自动发。
2. **再保证“边界可控”**：静默、每日额度、渠道单独授权、电话单次审批、重复任务幂等、用户可导出/删除；审计默认只记必要元数据。
3. **然后上线“自主生活”**：授权发现适配器 + 独立定时器 + 一次少量内容阅读 + 私有分享草稿；真实平台 API 和风控停止条件逐项验收。
4. **最后接 QQ 和其他终端**：通过外部适配器做账号映射，业务仍回 Whale Core。将 OneBot/QQ 视作可失效、不可信的外围平台。

## 尚未保证/已知约束

- `ProactiveOutbox` 是 **单工作者原型**：没有分布式事务/租约；不得在多个 Worker 并发自动发送时直接使用。
- `MemoryCurator` 是简单词项匹配（中文双字片段）、非语义向量，不会从原始音频自动总结，稳定事实冲突合并尚不存在。
- `DiscoveryPlanner` 只消费外部提供的内容元数据，不访问 B站，不抓视频、不写日志或评论。适配器对 `inspected` 声明负核实责任。
- `OwnerChannelRegistry` **不执行平台鉴权**，只在外部已鉴权结果上做所有者配对；不能把 `transport_authenticated=True` 当成无需审核的签名。
- `ProactiveOutbox` 中 `accepted` 是渠道接单确认，不代表已显示或已读；失败结果标记 `unknown`，不能自动重试。
- 原通话服务的文本入记忆开关是可选的；未经许可的转写不应启动持久化。未来应加入记忆授权开关和保留周期。
